## 1. Rules (every package)

1. **No transcript text in public output.** Nothing under `data/derived/corpus/raw/` is ever read by site code, and that includes the alias maps and `raw/asr-variants.json`. The one exception is `@emunas/corpus-guard`, which reads `raw/asr-variants.json` only to detect leaks, the same way it reads transcripts. `asrVariants`, `heardAs*` and every ASR-derived alias key never ship and are never indexed. `search/sections.jsonl` is not read at all, so `startSeg`/`endSeg` are never touched; the sites have their own time model. Public aliases and search synonyms come only from each entity's own display fields: `aliases`, `transliterations`, `canonicalHe`, `label`, `nameHe/En/Yi`, `titleHe/En`, `sefariaIndexTitle`, and topic `aliases`, which are used as synonyms but never displayed.
2. **Allow-list projection.** The reader allows exact file patterns and a deny rule is checked first (C1.1). Layer files are built by copying named fields, never by spreading records. A field the pipeline adds is unpublished until someone maps it on purpose.
3. **Guard.** It checks forbidden keys, bans raw/ content in alias positions, asserts that every published alias is a display field, and scans the new corpus text fields verbatim (C1.3). The guard post-pass on a real build must show **0 findings**.
4. **AI-generated and unreviewed.** Every corpus entity page carries the addendum's label once per page (Quiet C6 "The label", Live E.3). `reviewStatus: "reviewed"` swaps in the reviewed wording for that entity alone. No per-item badges.
5. **Visible shiurim only.** needs_review shiurim, and anything not `full` in `.corpus`, are never linked from a corpus entity. Every count, hub, grade, mix, thread and story is recomputed from the visible set (§3.2), never read from `shiurCount` or `shiurIds.length`.
6. **Languages.** Yiddish and English shiurim are separate shiurim, never translations. The "counterpart in the other language" item, the side-by-side series view and the series "also in <language>" link are removed (Live F.1; Quiet C4.1 "nothing pairs them"). Language is a property of each row, never of a group.
7. **Derived at build time, no hand lists.** Thresholds are rules over counts. Owner choices live in one config file (§2). The build tolerates the pipeline's shape changes (§3.1).
8. **Pipeline paths are read-only.** Nothing writes to `data/`, `scripts/`, `src/`, `config/` or `prompts/`.
9. **Every package's acceptance** includes its own unit tests and green `site:typecheck`, `site:lint` and `site:test`. The C3 integrator also runs e2e and the full real-data chain (§6).
10. **No backwards compatibility:** the sites have never been published; no redirects, stubs, legacy keys or compat shims.

## 3. Shared contract (fixed here so parallel packages can code against it)

### 3.1 Input rules (C1.1)

- **Allowed:** `data/derived/corpus/{index,topics,concepts,people,works,stories,teaching-clusters,redirects}.json`, `series/<seriesId>.json`, `shiur-tags/<shiurId>.json`. Nothing else.
- **Denied before the allow-list:** `raw/**` (alias maps, `asr-variants.json`, digests), any name containing `alias-map`, `asr`, `heard` or `variant`, the agents' working directories `topic-tags/` and `teaching-clusters/`, and `search/sections.jsonl`.
- **Shape changes tolerated:** loose schemas that ignore unknown fields. These are read when present: `reviewStatus`, `sameAs`, `otherSpeakerShare`, `mergedInto`, `kind` (work, story), `parsha`/`zman` on topics, `private`/`family`/`contemporary` on people. A future split of display aliases into a separate file is read only after someone adds its exact name to the allow-list (rule 2). A key named `asrVariants`/`heardAs*` is dropped on read and counted.
- **Failure policy:** corpus dir absent → layer off, with a warning. Core file malformed → fatal. Optional file missing or invalid → that feature off, with a report entry. Bad record → dropped and reported. Unknown `files` entries → listed by name as "not read".

### 3.2 The visible set

`V` = shiurim with `.corpus` status `full` ∩ corpus `index.shiurIds`. A member (telling, cluster member, hub, tagged shiur, arc part, exampleRef) counts only if its shiur is in `V` and the item it points to survived projection: the moment id exists, so low-confidence and suppressed items drop out. When D6 is on, tellings and cluster members must also come from a category with `generalBrowse: true`. Section-level topic tags on `other_speaker` chapters are dropped (Quiet C6 "Filters").

### 3.3 `.corpus/layer/` (C1.2; types in `@emunas/corpus/public`, `LAYER_SCHEMA_VERSION`)

| `concepts.json` | canonicalHe, label, definition (generated), visible shiurIds, visible exampleRefs, `passim`, `liveFacetDrop`, `mergedIntoTopic`, page flags |

## 5. Retired ids, no redirects

The sites have never been published, so there are no old addresses to keep (rule 10). Retired corpus ids (`redirects.json` and record-level `mergedInto`, chains resolved; a target may be of another kind, e.g. the person `moshiach` → the concept `mashiach`) are resolved inside the layer projection (C1.2) so that every reference (shiur tags, story people, `sameAs`, authors, parents) points at the surviving entity. Nothing about retired ids is published: no layer `redirects.json`, no Quiet `_redirects` or stub pages, no Live `/data/redirects.json` or 404 lookup. An id with no page is a 404 on both sites.

## 6. Integration and the real-data chain

Per wave the integrator merges the parallel worktrees, regenerates `package-lock.json` once, and runs `site:typecheck`, `site:lint` and `site:test`. The C3 integrator also runs `site:e2e` and the full chain on the repo's real data (`npm run site:chain`, C3.8):

```
corpus:build → guard pre → corpus:build --suppress → search:build → live data:build → quiet build → live build → guard post (0 findings) → budgets
```

The guard post-pass must report 0 findings. The job summary adds layer counts (visible recounts, pages per site, suppressed corpus ids, files "not read").
